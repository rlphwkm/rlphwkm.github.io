Wazuh SIEM Management in a Local Environment

November 12, 2025 5 min read

Deploying a Security Information and Event Management (SIEM) system in a homelab is one of the best ways to get hands-on experience with SOC analysis and incident response.

When building my local environment, I chose Wazuh because it provides an excellent open-source platform for threat detection, integrity monitoring, and incident response. This guide breaks down my deployment strategy using VMware.

The Architecture

I structured my network to isolate the logging environment from the general homelab traffic. The core component is the Wazuh server, which aggregates logs from various agents installed on both Linux and Windows virtual machines.

"Effective logging isn't just about collecting data; it's about making that data actionable."

Installing the Wazuh Agent

Installing the agent on a target Debian/Ubuntu machine is straightforward. You can deploy it using the official repository or via a direct curl command. Here is an example of the command used to install the agent:

wget https://packages.wazuh.com/4.x/apt/pool/main/w/wazuh-agent/wazuh-agent_4.4.1-1_amd64.deb
sudo WAZUH_MANAGER='10.0.0.50' dpkg -i wazuh-agent_4.4.1-1_amd64.deb
sudo systemctl daemon-reload
sudo systemctl enable wazuh-agent
sudo systemctl start wazuh-agent

Notice that we define the WAZUH_MANAGER environment variable directly inline so the agent knows exactly where to report its logs.

Dashboard & Rule Creation

Once the logs started flowing in, the next step was writing custom decoders and rules. By default, Wazuh maps common attack vectors, but building custom rules helps tailor the alerts to your specific environment.

  • Level 3 Alerts: Standard authentication failures.
  • Level 7 Alerts: Suspicious administrative access.
  • Level 10+ Alerts: Active exploitation attempts or malware detection.

This setup gave me incredible visibility into what was happening across my network.
